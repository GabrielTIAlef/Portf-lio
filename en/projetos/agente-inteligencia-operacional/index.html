01 / Context

The setting and the scope

In this independent project, I built an analytics, BI, SQL, automation and applied AI case around a fictional marketplace. My work spans data generation, ETL and PostgreSQL persistence, metric definitions, a React dashboard, a FastAPI service and a Gemini assistant with read-only tools. The dataset contains 1,000 orders from October 2026, five regions and three categories.

02 / Problem & objective

What needed to be solved

Order totals alone do not explain where cancellations and delays concentrate or which segments warrant investigation. The solution needed flexible exploration, consistent rule monitoring and natural-language access to metrics, with calculations remaining in the system.

04 / Challenges & decisions

Decisions behind the solution

  • Date, region, category and status filters define a consistent scope; comparisons use an equally long previous window when coverage is complete.
  • Clickable days and rankings support investigation. Preview and JSON share filters; changing scope invalidates export approval.
  • The monitor applies deterministic cancellation, delay and volume-drop rules with minimum counts, monitor_runs history and daily success control.
  • Gemini can call only authorized read tools, without arbitrary SQL. Chat keeps limited session context and the key remains on the server.
  • n8n calls the API in the local example; the HTTPS Oracle demonstration uses a systemd schedule at 09:00 São Paulo through the same API.

05 / Results & evidence

What can be reviewed

The delivery integrates a dashboard, monitor and assistant over the same synthetic dataset. In the documented 18–31 October 2026 screenshot, the dashboard shows 460 orders, R$62,047.31 in order value, 9.6% cancellations and 10% delays. These metrics guide segment investigation; order value includes every status and is not revenue. The demonstration is deployed with HTTPS, PostgreSQL and Gemini chat.

Public evidence

Actual dashboard, monitoring and chat screens, metric code, ETL, agent tools and deployment documentation. Local validation dated 12 November 2026 records 56 passing Python tests with PostgreSQL, frontend lint and build.
