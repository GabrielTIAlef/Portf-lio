01 / Context

The setting and the scope

Financial follow-up needed to combine Conta Azul receivables with information maintained by the team in Excel and Notion. My work connected automatic sources and operational controls to support delinquency and financial monitoring. The public version demonstrates the integration approach using fictional data and simulated services.

02 / Problem & objective

What needed to be solved

Clients sharing a name could not be matched by name alone, and API updates needed to preserve team-maintained fields. Delivery state also needed tracking when the database committed but Notion or file updates failed.

03 / Architecture & development

From source to delivery

  1. 01Conta Azul / Notion
  2. 02UUID contract
  3. 03PostgreSQL + outbox
  4. 04Excel / synchronization

A simplified reading guide. Repository documentation describes contracts, sources, stages and reproduction.

04 / Challenges & decisions

Decisions behind the solution

  • UUIDs link clients and receivables even when names match.
  • Updates preserve manually maintained follow-up fields.
  • Snapshots, batches and delivery intentions commit together; an outbox tracks Notion synchronization.
  • Ambiguous timeouts require identity-based recovery before retrying; a serial worker, debounce and polling coordinate file changes.

05 / Results & evidence

What can be reviewed

The professional work centralized follow-up and automated updates. In the public demonstration, three clients, including two with identical names, and two receivables have an outstanding balance of 130.00; reconciliation preserves amounts and manual fields while the outbox records each simulated delivery state.

Public evidence

Contracts, transactional publishing, synchronization and an Excel sample. Documentation records 65 tests, including 24 using real PostgreSQL, covering rollback, concurrency, timeouts and recovery.
